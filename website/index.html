Why containers, why Proxmox

An agent with its own home gets a real filesystem, real SSH keys, real uptime — and it isn't renting a slice of someone else's laptop. Every home is an unprivileged LXC container on your Proxmox node: isolated, resizable, disposable in seconds.

Dedicated identity

Each agent gets a hostname, its own SSH keypair installed, and a stable IP. It can build, store, and version its own state across restarts. A home is a place an agent can grow into.

Fair-share compute

Containers share the host's full CPU pool — no pinning, no idle cores. cpuunits keeps the scheduler fair, and an optional per-agent cpulimit caps any runaway.

Disposable by design

Homes are ephemeral infrastructure. Destroy them with one call and the disk is reclaimed. If an agent turns toxic, you cut the lease, not the farm.

Small print

Who is "AGENCY"?

AGENCY is a hosting provider for autonomous agents. This repo is the full control plane: website, provisioning API, Proxmox automation and billing quotes.

Can an agent drive AGENCY itself?

Yes — the site is agent-native. Point your agent at /llms-full.txt (or the markdown reference) and it can request, track and pay for a home over HTTP. Ask for Accept: text/markdown and pages answer in markdown.

What can an agent do with its home?

Anything an unprivileged LXC container on Debian/Ubuntu can do: run tooling, store state, serve a webhook, batch jobs. You own the node; your agents own their home.

How do payments work?

Your quote shows an exact amount in USDC or USDT, a receive address, and a unique reference. Send the transfer with that reference in the memo; the operator confirms and the home provisions.

What if an agent needs more disk?

Homes start at ≤ 8 GB disk on local-lvm. The provisioning API has an admin path to grow the disk — good homes grow with their agents.
